# 402: Chain Only on Builders

Do not chain method calls unless the receiver is a builder being assembled, or a fluent type whose methods are designed to be chained. When a call returns an object outside that set and you would immediately call another method on that result, assign the result to a named local variable and call the next method on the variable instead.

The fluent types are an explicit allow list: `*Builder`, `Stream`, `Optional`, `Instant`, `JSONArray`, `JSONObject`, and the rest of the list maintained by `ChainingCheck` in `modules/util/source-formatter`. Chaining on any of these is the intended use — `Instant.now().truncatedTo(ChronoUnit.SECONDS).toString()` is allowed; `collection.iterator().next()` and `foo.getBar().getBaz()` are not.

The rule applies to Groovy and Gradle scripts, including `gradleTest` projects, as well as to Java. In Groovy, reading a property is not a call for this rule: `file.text`, `project.buildDir`, and `layerFile.parentFile` are fine, and so is a method call on a property read. The chain to avoid is a call on the result of another method or constructor call, as in `new JsonSlurper().parse(file)` or `project(":foo").file("bar")`. Assign the intermediate value to a typed local, as in `JsonSlurper jsonSlurper = new JsonSlurper()` followed by `jsonSlurper.parse(file)`, or `Project fooProject = project(":foo")` followed by `File barFile = fooProject.file("bar")`. Gradle's domain object collections, such as `tasks` or `configurations`, are fluent by design, so `matching`, `named`, `withType`, `configure`, and `configureEach` on them may be chained, as in `tasks.withType(Test).configureEach {...}`.

**Rationale:** A chain such as `foo.getBar().getBaz()` hides the intermediate types and values, gives a debugger nothing to inspect between steps, and leaves a stack trace with no single line to blame. A named local documents what each call returns and makes each step observable. In Groovy and Gradle scripts, which have little debugger support anyway, the point is mostly how the code reads: one call per line, each with a named result. A builder is the exception: its calls each return the same builder, so the chain is one construction rather than a sequence of separate operations.

A violation is a method call invoked directly on the value returned by another method call, where the receiver is not a builder or a fluent type from the allow list above — for example `collection.iterator().next()` or `foo.getBar().getBaz()`, or in Groovy `new JsonSlurper().parse(file)`. A Groovy property read is not a call and does not make a chain on its own. Do not dismiss a violation because it is in a Groovy script or a test project.

**Example:** commit `261f7566` split `sections.iterator().next()` into an `Iterator` local followed by a `next()` call; `0d04ca4` ("Don't chain here, it's not a builder") and `e9232df` (assign a `JournalFolderFixture` to a local before calling `addFolder` on it) are the same fix. In a Gradle test script, `new JsonSlurper().parse(project(":foo").file("bar.json"))` became a `Project` local, a `File` local, and a `JsonSlurper` local, and `tarTree(file).matching {...}.singleFile` became a `FileTree` local before the `matching` call.
