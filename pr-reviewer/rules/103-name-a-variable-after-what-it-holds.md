# 103: Name a Variable After What It Holds

Name a variable after what it holds, not after an incidental role. Usually the plain name of the content is enough, with no type suffix: a `String` is `name`, not `nameString`, and when only one value of a type is in scope, the type name itself works (`jsonObject`, `enumeration`, `file`). Put the type or form in the name only to tell values apart. A value held in a different form than its plain name suggests says so: a `String` that holds JSON ends in `JSON`, as in `objectDefinitionJSON`, and a `Page` ends in `Page`. When a qualifier distinguishes several values of the same type, the type follows the qualifier: two descriptor maps are `ableDescriptorMap` and `bakerDescriptorMap`, not `able` and `baker`. This applies in Groovy and Gradle scripts as much as in Java.

A collection or array takes the plural and needs no type suffix: `String[] ids` and `List<String> ids` are both correct. A suffix such as `idsArray` or `idsList` is optional, and only earns its place when two collections of the same content share a scope, such as a `String[]` and a `List<String>` of the same IDs; even then, one of them can stay the plain plural.

**Rationale:** A name that says what the value holds tells the reader what they are handling without tracing back to the declaration. A name taken from an incidental role (`metadata`, `userValue`, `result`) hides that, and invites a mismatch between the name and the value. A type suffix earns its place only when it resolves a real ambiguity; on a lone `String` or a plural collection it is noise.

A violation is a variable named for an incidental role rather than what it holds; a name whose stated type or form does not match the value, such as a `String` of JSON named `objectDefinitionString` rather than `objectDefinitionJSON`, or a collection named as if it held a single element; or a qualifier used alone as a name, such as a `Map` named `able` next to another descriptor map. A name without a type suffix is not a violation, as in `String name`, `String[] ids`, or `List<String> ids`, unless a similarly named variable in the same scope makes it ambiguous. Do not suggest adding a type suffix to such a name.

**Example:** commit `a8af2ca` renamed `metadataJSONObject` to `jsonObject`; `ec36099` renamed `objectDefinitionString` to `objectDefinitionJSON` because it holds JSON; `84d9629` renamed `getAgentDefinitions` to `getAgentDefinitionsPage` because it returns a `Page`; `320d3dc` renamed the vague `result` to `json`, the JSON that `getJSON` returns. In a Gradle test script that read two descriptor maps, the `Map` locals `able` and `baker` became `ableDescriptorMap` and `bakerDescriptorMap`.
